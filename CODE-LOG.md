# Журнал кода — ByeDPI Автозапуск

## 2026-11-25 20:05 — создан проект

**Задача.** Аналог iOS-команд для Android: при открытии YouTube/Instagram включать ByeByeDPI,
держать VPN, перезапускать после обрыва, после выхода из приложения выключать и убирать процесс.

**Решение.** Отдельное приложение-компаньон `ru.dsh.byediautostart`. Управляет официальным
ByeByeDPI через его `ToggleActivity` (extras `only_start` / `only_stop`), сам VPN не поднимает.
Слежение за активным приложением — `AccessibilityService`, состояние VPN — `TRANSPORT_VPN`.
Пауза после ухода 15 с, реконнект каждые 5 с.

**Файлы.**

| Файл | Назначение |
|---|---|
| `app/src/main/java/ru/dsh/byediautostart/AppWatcherService.kt` | служба доступности + резервный тикер |
| `AutomationCore.kt` | чистая логика переходов, покрыта тестами |
| `AutomationController.kt` | связка событий, настроек, watchdog |
| `ByeDpiClient.kt` | поиск ByeByeDPI и отправка `only_start`/`only_stop` |
| `VpnMonitor.kt` | проверка `TRANSPORT_VPN` |
| `WatchdogService.kt` | foreground-сервис на время сценария |
| `MainActivity.kt`, `AppPickerActivity.kt`, `AppListAdapter.kt` | UI и выбор приложений |
| `Prefs.kt`, `Notifications.kt`, `AutomationState.kt` | настройки, уведомления, состояние |
| `app/src/test/.../AutomationCoreTest.kt` | 8 unit-тестов |

**Ключевая логика.**

```kotlin
fun onForeground(pkg: String, now: Long): Foreground {
    if (pkg in neutral) return Foreground.NEUTRAL
    if (pkg in targets) {
        val wasActive = targetActive
        targetActive = true
        stopAt = null
        lastTargetPackage = pkg
        return if (wasActive) Foreground.NONE else Foreground.ENTERED_TARGET
    }
    if (!targetActive) return Foreground.NONE
    targetActive = false
    stopAt = now + graceMs
    return Foreground.LEFT_TARGET
}
```

```kotlin
Intent()
    .setComponent(ComponentName(pkg, pkg + ".activities.ToggleActivity"))
    .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
    .putExtra(if (start) "only_start" else "only_stop", true)
```

**Сборка.** `build.cmd assembleRelease`. AGP не принимает кириллицу в пути, поэтому `build.cmd`
создаёт junction `A:\byedpi-build` и собирает через него. Инструменты: `A:\AndroidToolchain`
(JDK 17.0.21, SDK 34, build-tools 34.0.0, Gradle 8.7).

**Проверки.** `assembleDebug` — успешно; `testDebugUnitTest` — 8/8; `assembleRelease` — см. ниже;
`lintDebug` — см. ниже. На реальном телефоне не проверялось: устройство не подключено.

**Ограничения.** Без root полный force-stop невозможен: только остановка VPN-сервиса и
`killBackgroundProcesses`. Always-on VPN у ByeByeDPI должен быть выключен.

## 2026-11-25 20:29 — исправления по независимому ревью

Ревьюер нашёл 6 сценариев, в которых VPN мог остаться включённым. Исправлено:

1. **Остановка не сдаётся после 3 попыток.** Вместо `finishCycle` при живом VPN — повтор
   `only_stop` каждые 30 с и уведомление «ByeByeDPI не выключается» (а не молчаливое
   завершение watchdog).
2. **Смена списка приложений во время паузы.** `AutomationCore.restore()` переносит
   `targetActive`, `lastTargetPackage` и `pendingStopAt` в новый экземпляр; дедлайн больше
   не теряется.
3. **Мёртвая ветка `typeWindowsChanged`.** Событие не приходит без
   `flagRetrieveInteractiveWindows`, а с флагом давало бы ложные «уходы». Убрано из конфига
   и кода, остался `typeWindowStateChanged`.
4. **`onDestroy` службы доступности** теперь тоже вызывает `onWatcherDisabled()` (с защитой
   от повторного вызова): VPN гасится, даже если `onUnbind` не пришёл.
5. **Пустое состояние после перезапуска процесса.** Добавлен `hasState()`: если нет ни цели,
   ни паузы, watchdog останавливается независимо от того, включён ли VPN.
6. **Выключение тумблера «Автоматизация»** при активном целевом приложении теперь отправляет
   `only_stop` и убирает процесс, а не оставляет VPN включённым.

Добавлены 2 unit-теста на перенос паузы и `hasState` — всего 10/10.

Повторная проверка на эмуляторе Android 14:

- открытие Settings → VPN поднялся; выключение тумблера → `ToggleServiceActivity: stop`, VPN выключен;
- удаление службы доступности (`settings delete secure enabled_accessibility_services`) →
  `ToggleServiceActivity: stop`, VPN выключен;
- штатный цикл «открыл → свернул → 15 с → стоп» по-прежнему работает.

## 2026-11-27 00:50 — версия 1.25: исправлено падение настроек

**Задача.** При нажатии на «Настройки» приложение сворачивалось.

**Причина.** `StatusBarCard.apply()` вызывался в `SettingsActivity` до `setContentView`.
`WindowInsetsControllerCompat(activity.window, root)` обращался к ещё не созданному
`DecorView` → `NullPointerException` в `PhoneWindow.getInsetsController`.

**Сделано.**

- `StatusBarCard.apply(this, root)` перенесён **после** `setContentView(root)`.
- Остальные активности уже вызывали его после `setContentView`.

**Проверки.** `assembleRelease`, 14/14 тестов. На телефоне «Настройки» открываются,
logcat без `FATAL EXCEPTION`.
